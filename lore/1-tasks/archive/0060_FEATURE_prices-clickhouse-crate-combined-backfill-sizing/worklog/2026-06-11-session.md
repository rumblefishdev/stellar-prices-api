## Key findings / decisions
- Both SDEX trades and soroban events come from the same `LedgerCloseMeta` →
  single-pass backfill confirmed feasible (no BE `soroban_events` table dep).
- **Soroswap token resolution gap:** `swap` events carry no token addresses;
  the pool→tokens registry comes from factory `new_pair` events that mostly
  precede our recent 100k window (62882700–62982700). Aquarius/Phoenix carry
  tokens inline so they resolve in-window; Soroswap pools created before the
  window will be unresolved unless the registry is seeded from history.
  → Handle explicitly when wiring (seed registry, or document Soroswap coverage).
- Oracle: REFLECTOR = JSON map (`update_data` vec of [symbol|address, i128@1e14]);
  REDSTONE = base64 XDR ScVal bytes (needs decode), ~4 feeds, 1 contract.
